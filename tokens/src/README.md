# tokens/src

DTCG sources, hand-edited; `dist/` outputs are generated by `npm run build:tokens`, never edited.
- Tiers: `ref/` primitives (`--vn-ref-*`, private), `sys/` semantic (`--vn-*`, alias refs), `component/` (`--vn-{component}-*`, alias sys).
- Naming: lowercase kebab; DTCG path joins to the CSS name (`button.signal.bg.hover` -> `--vn-button-signal-bg-hover`; `$root` is the group's own value).
- Dark values live in `$extensions.vn.dark` of each sys color; `$value` is light. `$extensions.vn.pending` marks a theme the plan does not define yet.
- Format: DTCG 2025 object form (color `{colorSpace, components, hex}`, dimension/duration `{value, unit}`).
- Ref paths: the DTCG path keeps the category (`ref.color.red.600`), but the build drops that segment for refs, so the CSS name is `--vn-ref-red-600` (`ref.space.64` -> `--vn-ref-space-64`, `ref.font.weight.bold` -> `--vn-ref-font-weight-bold`: only the leading `color` segment is dropped, since color steps are unambiguous).
- Components never alias `ref.*`; they alias `sys` tokens only (checked by the validator).
- Typography: `sys/type` styles are `typography` composites. `letterSpacing` is px at the reference size; the em source is `$extensions.vn.tracking`, and fluid sizes are `$extensions.vn.fluid` (the build emits those).
- `radius.round` is `number` 50 with `$extensions.vn.unit: "%"` (DTCG has no percent dimension). Shadows keep dark in `$extensions.vn.dark` as a full shadow value.
